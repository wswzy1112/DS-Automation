
## 1.Multi-Step Agent Workflow介绍
Multi-Step Agent Workflow即多步代理工作流，宏观上指AI代理在完成任务的时候，并不是一步给出答案，而是把任务拆分为多个子集，然后在逐一执行的过程中不断进行“思考，行动，观察”的策略，通过多次迭代最终逼近目标。
为什么会需要多部代理工作流？
- - **任务复杂度**：现实问题往往无法一步解决，所以需要将任务拆分为多个子任务。
- **工具依赖**：代理常需调用外部 API、搜索引擎、数据库或代码解释器，每次调用都是独立的一步。
- **动态纠错**：单步推理一旦出错便无法挽回，多步流程允许中间检查与回滚。
- **可解释性**：每一步的输入输出均可追溯，便于调试和审计。
## 2 Single-Agent Multi-Step Workflow介绍
Single-Agent Multi-Step Workflow即单代理多步工作流，就是一个AI代理独立完成从拆解任务-逐步执行-动态调整-交付的任务，是所有代理系统的基石，同时也是目前绝大部分AI的模型形态。
单代理多步工作流的核心特征有：
 - 唯一决策者：在完成任务的过程中，全程只有一个智能体进行推理思考行动的工作。
 - 迭代不断循环：实现目标的过程中，一直遵循着‘’思考-行动-观察’‘的策略，并不是一次直接得出答案，反复调用模型，直到任务完成。
 - 呈线性或者树状的形态推进： 在完成任务的过程中，虽然存在分支以及反思，但是整体是在同一个context窗口中进行的，沿着一条主线不断推进。
## 3 Multi-Agent Multi-step Workflow介绍
 Multi-Agent Multi-step Workflow即多代理多步工作流，即宏观上而言，是由多个Ai代理协同合作循环来完成任务，微观上而言，每个Agent内部仍是单代理多步工作。每一个Agent都有属于子的工作，所有的Agent协同工作以此来完成目标。
**核心构件**
- **Orchestrator/Supervisor**:属于编排者，并不执行具体的工作，只负责从用户接收任务，将任务拆分，决定代理谁先谁后，回收执行结果，判断是继续还是回退。
- **Specialist Agents**：每个都有属于自己的工作，例如分析数据，或模型构建，或监管
- **Handoff**：即交接协议，当某一代理的任务完成之后，并不是直接告诉后面我的任务已经完成，该你执行。每一次的Handoff都需要附带上task contrext,输出，日志，置信度等信息。
- **共享状态**：跨代理的长期记忆常放在 StateGraph、向量库、消息总线里，避免每个 agent 都从头了解一遍全量上下文。
- **终止与安全阀**：最大轮次、最大 revision 次数、超时、loop detector、human-in-the-loop，是生产级多代理多步系统的标配，否则容易死循环或空转。
